## 模块五修复

P6.5 有两种输出：

- 7列：player、source、season、apps、goals、pens、ownGoals。
- 8列：league、season、apps、shots、goals、xG、assists、penGoals。

原解析只判断“至少7列”，把8列俱乐部文件吞入7列解析器，使赛季变成出场次数、球员变成联赛名。

修复后：

1. `HistoryParser.parseCareer` 为 HTTP 和 MySQL 导入共用的逐行分派入口。两种格式按精确列数、赛季位置、source 和有效数值识别；xG 为整数也能识别。错误行返回400，避免误解析后覆盖旧数据。
2. 8列文件保留 league、season、出场次数、进球、xG；7列保留 player、source、season、出场次数、进球、点球。支持 WC-2022。接口增加 secondaryMetric 说明副指标是 xg 还是 penalties。
3. 页面增加实际覆盖赛季的筛选，显示“出场次数”和副指标口径；修复 xG 被四舍五入成整数的问题，中英文标签同步。
4. 重新导入本机 run `local-mysql-20261030` 的 P6.5 数据，其他分析分支的数量保持一致。不需要重新训练或重跑 Hadoop。

实际19条记录逐行核对通过。第一条现在是：La Liga、2004-05、7次出场、1球、xG=0.57。8列源文件不含球员姓名，接口 player 保留 NULL，不从数据中推造姓名。文件当前为 messi_club.tsv；如后续需要通用多球员生涯，应让导出结果显式携带球员身份。

## 其他电脑如何更新

合并本次源码或替换新 JAR，重建前端资源后启动。数据库无需新增字段：history_point 仍保存 dimension=club、value_num=进球、value_second=xG、cnt=出场次数。

对每个曾导入错误 P6.5 的 run 执行一次重导入，例如：

```bash
curl -X POST http://127.0.0.1:8080/api/admin/import/history/local-mysql-20261030 \
  -H 'Content-Type: application/json' \
  -d '{"analysis":"P6.5","location":"runs/p65-194220/module5/messi_club.tsv"}'
```

location 相对于 footpred.local.root；替换代码不会自动纠正旧数据库记录，必须重导入。
