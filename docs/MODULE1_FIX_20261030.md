# 模块一 DC预测入口修复

修复位置为Web后端的结果读取/解析和导入，以及前端的空结果提示。

## 已确认的问题

1. `ResultController`的RF和DC默认读取相同文件，但RF是11列历史回测格式，DC是6/7列对阵预测格式。
2. `MatchPredictionParser.parseDixonColesPrediction`没有检验对阵标识、概率、进球强度，错误文件产生NaN和非法概率。
3. 当前仓库的两份`partner/predictions.tsv`均为0字节，不能拿测试fixture或RF结果冒充真实DC预测。

## 修改后的行为

- RF继续使用`footpred.result.matches`，保持已有1752场测试结果。
- DC单独使用`footpred.result.matches.dixon-coles`。请求中的显式`location`仍可覆盖路径。
- 没有配置、文件缺失或空文件：HTTP200、available=false、count=0，并带note/message明确说明。
- 明确选错格式或所有行非法：HTTP422、invalid-prediction-format；不再返回伪预测。
- 解析器拒绝RF行、表头、缺少`home vs away`的记录、非有限/越界概率、不归一的概率和负数/非有限进球强度。
- DC导入无有效记录时返回partial并保留该run/source已有记录，不会先删除有效历史数据。
- 前端空状态显示后端note；前端dist与后端内置static同步修改。

## 补充真实DC结果

从实际DC `predict`作业的HDFS输出导出文件，放到独立DC路径，或通过启动参数`--footpred.result.matches.dixon-coles=实际文件路径`指定。

一行格式：`home vs away<TAB>p_home<TAB>p_draw<TAB>p_away<TAB>lambda_home<TAB>lambda_away<TAB>top_scores`。

`top_scores`可选；若存在则是以`|`分隔的比分及概率。胜平负概率必须在0到1之间且和为1，双方进球强度必须为非负有限数。生产数据目录没有填入测试样例。

后续已在Linux使用真实已训练模型运行国家队6场、俱乐部5场预测，并将11条实际MR结果接入默认路径。详细Job、HDFS目录和校验证据见`DC_LINUX_REPLAY_20261030.md`。原写出器的概率只保留4位小数，允许三项之和在1±0.00015内，保留原始舍入值。

本轮只处理模块一入口。球员跨赛季聚合、P6.5生涯解析及通用前端build路径问题留待对应模块处理。修改保存在本地工作副本，尚未提交或推送GitHub。
